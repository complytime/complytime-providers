# NAME

complyctl-provider-openscap - OpenSCAP scanning provider for complyctl

# SYNOPSIS

**complyctl-provider-openscap**

# DESCRIPTION

**complyctl-provider-openscap** is a gRPC plugin for **complyctl**(1) that
provides compliance scanning capabilities using the OpenSCAP engine. It is
not invoked directly by users; **complyctl** discovers and launches it
automatically when the provider is installed.

The provider receives assessment configurations from **complyctl**,
generates XCCDF tailoring files matching the requested profiles, executes
scans via the **oscap** command-line tool, and returns structured results.
It supports automatic datastream selection via CPE-based matching against
the host system.

Communication with **complyctl** uses the hashicorp/go-plugin gRPC
interface, implementing three RPCs: **Describe**, **Generate**, and
**Scan**.

# CONFIGURATION

Configuration is provided through variables defined in assessment plan
targets. These variables are passed to the provider via **complyctl** and
are not set manually by the user.

**profile** (required)
:   XCCDF profile ID to evaluate. Must match the pattern
    **[a-zA-Z0-9-_.]+**. Examples: **cis_server_l1**,
    **xccdf_org.ssgproject.content_profile_cis**.

**datastream** (optional)
:   Path to an SSG XCCDF datastream XML file. Relative paths resolve against
    the selected workspace; absolute external paths remain absolute. When omitted, the
    provider auto-detects the appropriate datastream by matching the
    system's CPE (from the os-release file) against CPE metadata embedded
    in the SSG datastream files.

**workspace** (host supplied)
:   Coordinate and artifact root supplied through Generate global variables and
    Scan target variables. **complyctl** selects **--workspace**, then
    **COMPLYTIME_WORKSPACE**, then the invoking directory. Providers use the
    supplied value without repeating that precedence. Missing/empty values fall
    back to provider CWD for direct callers; invalid or conflicting roots fail the RPC.
    Relative workspace values resolve against provider CWD, including root symlinks.
    Tool subprocesses use the resolved workspace without changing provider CWD.

# ENVIRONMENT

**SSG_CONTENT_DIR**
:   Directory containing SSG datastream XML files. Used during
    auto-detection when **datastream** is not specified.
    Default: **/usr/share/xml/scap/ssg/content**

**OS_RELEASE_FILE**
:   Path to the os-release file used for CPE extraction during
    datastream auto-detection.
    Default: **/etc/os-release**

**COMPLYTIME_MACHINE_ID_FILE**
:   Path to the machine-id file used for host identification in
    evidence remarks. The file content is included in each
    Evidence.Source.Remarks field alongside the hostname so auditors
    can identify the host where the scan was executed.
    Default: **/etc/machine-id**

# EXTERNAL TOOLS

Requires **oscap** (provided by the **openscap-scanner** package) at
runtime. The provider locates **oscap** via **PATH** lookup.

The **scap-security-guide** package provides the SSG datastream files
used for evaluation.

# FILES

*.complytime/openscap/*
:   Provider workspace directory. All paths below are relative to the
    selected workspace root, not the log directory or the reader's CWD.

*.complytime/openscap/policy/tailoring.xml*
:   XCCDF tailoring file generated by the **Generate** RPC. Contains
    the selected profile rules matched from the assessment configuration.

*.complytime/openscap/results/\<target\>/\<profile\>/evaluation-\<time\>-\<token\>/arf.xml*
:   Asset Reporting Format (ARF) result file produced by
    **oscap xccdf eval --results-arf** during the **Scan** RPC.

*.complytime/openscap/results/\<target\>/\<profile\>/evaluation-\<time\>-\<token\>/results.xml*
:   XCCDF results XML file produced alongside the ARF file by
    **oscap xccdf eval --results**.

*.complytime/openscap/results/\<target\>/\<profile\>/evaluation-\<time\>-\<token\>/metadata.json*
:   Best-effort supporting context: request target, observed ARF target, profile,
    datastream and tailoring paths. This file is not evidence authority and contains
    no artifact digests. Internal provenance paths are workspace-relative; external
    paths remain absolute. Metadata write/close failures warn without suppressing
    otherwise complete evidence; the file can be absent or incomplete.

Target/profile labels are bounded readable grouping hints, not unique identities.
An absent request target uses **system**. Time uses UTC **YYYYMMDDTHHMMSSZ**;
each token has at least 128 bits of cryptographic entropy. Generate-time tailoring
and remediation paths above remain replaceable, not historical policy snapshots.

*.complytime/openscap/remediations/remediation-script.sh*
:   Bash remediation script generated by **oscap xccdf generate fix**
    during the **Generate** RPC.

*.complytime/openscap/remediations/remediation-playbook.yml*
:   Ansible remediation playbook generated by **oscap xccdf generate fix**.

*.complytime/openscap/remediations/remediation-blueprint.toml*
:   Blueprint remediation file generated by **oscap xccdf generate fix**.

# EVIDENCE

The provider records an **Evidence** entry on each **AssessmentLog**
returned by the **Scan** RPC:

**Type**
:   **ARF** — Asset Reporting Format. The ARF file aggregates XCCDF
    results, OVAL definitions, and system characteristics into a single
    SCAP-standard artifact.

**Production**
:   The ARF file is produced by running **oscap xccdf eval --results-arf**
    against the tailoring file and the SSG datastream. It is written to
    the fresh target/profile evaluation directory shown under **FILES**, alongside
    required supporting XCCDF output. Valid noncompliant results are retained too.

**EvaluationLog representation**
:   Each assessment log carries an Evidence entry with:

    - **ID**: **arf_\<token\>**, shared by assessments from one evaluation
    - **CollectedAt**: UTC RFC 3339 collection start, captured before tool execution
    - **Source.Coordinate**: selected-workspace-relative path to retained **arf.xml**
    - **Source.Digest**: **sha256:\<hex\>** digest of the ARF file
    - **Source.ReferenceID**: **openscap-arf_\<token\>**, matching a mapping reference
      with an escaped absolute **file://** URL to the same artifact

The Gemara Evaluation Log alone defines the evidence set through its evidence
entries and mapping references. Supporting XCCDF and metadata files are not
implicitly evidence. Resolve each coordinate against the selected workspace root,
or use its absolute file URL, and check the file's SHA256 digest against the log.
URI escaping preserves spaces, percent signs and non-ASCII names. Absolute URLs
describe the originating filesystem; copying the workspace preserves relative
coordinates but does not relocate those URLs.

Preservation is always on, with no automatic cleanup or retention settings. Each
scan stores a separate output set even when bytes match. Storage grows with scans,
including unreferenced partial outputs left by failures. Allocation, required
output/close, parsing, hashing and finalization errors fail the RPC without a response;
no earlier fixed-path result substitutes for missing output.

Evaluation directories are **0700** and evidence/supporting files are **0600**,
owned by the provider execution account. Sudo and direct-root scans keep root-owned
evidence; the original non-root user needs authorized elevated reading/hashing.
Environment or RPC ownership claims do not select another owner. The account needs
a writable workspace and traversal access through all parents; new context parents
permit traversal without widening evaluation leaves or changing unrelated directories.
For permission errors, verify the execution account and parent access. For disk-space
errors, provision sufficient writable capacity. Do not widen private evidence modes
or assume partial outputs are published evidence.

Preserve the Evaluation Log and its referenced files separately: uploading only the
log does not transfer artifact bytes. Downstream collection must preserve both,
keep log-selected files retrievable, verify transferred bytes against logged digests,
and map moved artifacts to original references without modifying the log. Collection,
validation of collected copies and optional packaging are separate future complyctl
capabilities, not implemented here. Storage backends and longevity remain customer-owned.

**Breaking upgrade behavior:** paths and evidence/reference IDs are now evaluation-qualified,
without fixed-path aliases. Relative input/configuration lookup now uses the selected
workspace rather than invocation CWD; migrate invocation-relative configurations.
Existing fixed-path outputs stop being refreshed; they and historical logs remain
untouched and are not migrated. Already overwritten evidence cannot be recovered.
Older binaries resume overwrite
behavior on rollback while retained evaluation directories remain readable by authorized users.

# EXIT CODES

This provider is a gRPC subprocess managed by **complyctl**. Exit codes
follow the hashicorp/go-plugin protocol and are not user-facing.
