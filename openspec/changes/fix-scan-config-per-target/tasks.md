# Tasks

## 1. Shared content-key and index infrastructure

- [ ] 1.1 Create a shared `internal/genindex` package with `ContentKey(requirementIDs []string, policySourceID string) string` that returns the first 16 hex characters of the SHA-256 of sorted, newline-joined requirement IDs followed by a newline and the policy source identifier. Verify with unit tests that: identical inputs produce the same key, different requirement IDs produce different keys, and identical requirement IDs with different policy source identifiers produce different keys.
- [ ] 1.2 Add `GenerateIndex` struct and `ReadIndex`/`WriteIndex` functions to `internal/genindex` that read and write `generate-index.json` with schema `{"version":1,"targets":{"<target-key>":"<content-key>",...}}`. Verify with unit tests covering create-new, read-existing, update-entry, and malformed-file-error cases.
- [ ] 1.3 Add `UpdateIndex(indexDir, targetKey, contentKey string) error` convenience function that performs the read-modify-write cycle. Include a source code comment noting that concurrent complyctl instances sharing the same workspace may race on this file and that file-level locking is a future consideration. Verify with a unit test.
- [ ] 1.4 Add `TargetKey(urlOrPath string) string` to `internal/genindex` that produces a collision-resistant index key from either a URL or an `input_path` value. For URLs: parse with `net/url.Parse`, strip scheme and `userinfo@` (credentials), then return the first 16 hex characters of the SHA-256 hash of the normalized result. For `input_path` values: `filepath.Clean` the path, then return the first 16 hex characters of the SHA-256 hash. Credential stripping prevents leaking tokens into index keys and ensures URLs with and without embedded credentials produce the same key. Hashing instead of character replacement avoids the lossy sanitization problem in the existing `SanitizeRepoURL` where distinct URLs (e.g., `github.com/org/repo` and `github.com:org/repo`) could collide. Verify with unit tests covering: URLs with and without credentials producing the same key, distinct URLs producing different keys, `input_path` values producing valid keys, and `input_path` targets producing different keys from URL targets to the same host.
- [ ] 1.5 Add `ValidateContentKey(contentKey, generatedDir string) error` to `internal/genindex` that validates the content key matches the expected hex format (`^[0-9a-f]{16}$`) and that the resolved absolute path is contained within the generated directory (no path traversal). Returns an error describing the validation failure. Verify with unit tests covering: valid hex key, key with path traversal (`../etc`), key with invalid characters, empty key, and key of wrong length.
- [ ] 1.6 Retain the existing `SanitizeRepoURL` functions in both providers' `targets` packages for their current non-index uses (result file naming) where human readability matters and collisions are acceptable. Verify that callers of `SanitizeRepoURL` (`cmd/opa-provider/loader/loader.go`, `cmd/ampel-provider/scan/scan.go`, `cmd/ampel-provider/results/results.go`) continue to compile correctly — no changes expected for these callers since they use `SanitizeRepoURL` for file naming, not index key derivation.
